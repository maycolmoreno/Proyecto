6 archivos centrales, uno por rol arquitectónico (entidad de dominio, caso de uso, repositorio, controller, 2 middlewares), elegidos porque juntos muestran el ciclo completo de una request real y ya fueron leídos completos y verificados en documentos anteriores. Los archivos generados automáticamente (Prisma Client, `dist/`) o de configuración pura no se explican línea por línea aquí — su función general ya está cubierta en `07_LIBRERIAS.md`/`09_DOCKER.md`.

## 6. Conceptos de TypeScript/JS explicados de forma transversal (para preguntas sueltas de defensa)

- **`import`/`export`:** todo el proyecto usa ES Modules (`import`/`export`), no `require`/`module.exports` de CommonJS — confirmado por `"type": "module"` implícito en la config de `moduleResolution: NodeNext` de `tsconfig.json`.
- **`async`/`await`:** en el 100% de las operaciones de I/O (BD, IA, Cloudinary) — nunca callbacks anidados ni `.then()` encadenado en el código de aplicación.
- **`try/catch`/`finally`:** en los controllers, el patrón es siempre `try { ... } catch (error) { next(error) }` — delega el manejo real al middleware global, nunca responde el error directamente desde el controller.
- **Desestructuración:** usada tanto en parámetros de función como en asignaciones (`const { page, limit, sort, ...filtros } = ...`).
- **Clases y constructores:** toda entidad, caso de uso, repositorio y adaptador es una clase — nunca funciones sueltas con estado mutable global.
- **Inyección de dependencias:** siempre por constructor, siempre con `private readonly`, siempre resuelta una única vez en `di-container.ts`.
